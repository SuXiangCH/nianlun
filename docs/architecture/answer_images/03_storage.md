## 历史保留与持久化

<a id="s7-1"></a>

### 选择归档，不长期占用旧 snapshot

当前 snapshot 的进程内引用计数不能保证历史会话永久读取旧资源。
第一版将本轮已检索且允许查看的图片复制到独立的私有归档，按知识库与内容摘要去重。
归档默认本地文件，可配置 MinIO/S3，后端不影响消息/附件或 URL/Data URL 契约；
详细存储端口、上传预约/租约和对象 GC 见 [10 图片存储](10_blob_storage.md)。
按 [文件类型、限额与错误](07_policy.md#s11) 本轮策略归档答案实际引用的图片，来源预览使用独立的较小剩余预算；来源面板只展示成功归档的集合。
这样旧 generation 清理后，已完成会话仍有当时的原图。
优先归档已选中的答案图片，再按片段读取顺序处理其余来源图片，避免来源预览耗尽答案配额。
来源预览与答案图片共用 `message_images`，仅预览的附件设 `display_in_answer=false`；
控制台返回并允许读取这些已归档附件，公开投影和 grant 签发只选择答案图片，
具体响应规则见 [控制台响应契约](04_console.md#s8-1) 和 [原生 API](05_public_api.md#s9-1)。

读取和复制时持有对应 snapshot/generation 的有效引用，不能在 runtime 释放后再按
“当前版本”查文件。归档保留原始图片字节，不把临时截图或缩略图误称为原图。

<a id="s7-2"></a>

### 拟新增持久化记录

| 记录 | 关键字段与约束 |
| --- | --- |
| `answer_image_blobs` | ID、知识库 ID、摘要、媒体类型、尺寸/方向、backend/profile、object key/可空版本 ID、生命周期状态；活动 uploading/ready 的 `(knowledge_base_id, sha256)` 唯一，retired/deleting/deleted 保留回收定位但不阻塞新归档，见 10 |
| `message_images` | 附件 ID、message ID、可空 blob ID、ref_ids、occurrences、来源绑定列表、顺序、可信图题、是否出现在答案、可用状态及原因 |
| `image_access_grants`，第二阶段 | grant ID、附件 ID、客户端 ID、应用 ID、签发 Key ID、token 摘要、过期时间、撤销时间 |

附件归属以服务端消息和会话关系为准，不接受客户端自报归属。
每个来源绑定包含文档 ID、generation、content version、image ID 和 citation ID；
通过严格的 Pydantic 结构校验后序列化保存，不使用无约束字典。同一摘要来自不同文档时，
保留全部绑定，不能只存一个 document ID 再附上其他文档的引用编号。
数据库通过向前迁移新增表；旧消息的附件清单自然为空，不要求回填。
同时为消息新增 `answer_output_mode` 字段，默认 `text`，用于历史恢复，不从正文或图片数量猜测用户意图。
用于 [多轮对话中的图片指代](02_agent.md#s6-5) 的节点和字符窗口从本消息已保存的来源定位取得，保证与附件绑定对应；
历史图片投影按需从消息及附件重建，不另存一份可独立变化的图片权限或选择状态。
规范 Markdown 中的逻辑图片引用与附件绑定同事务保存，新增 `answer_format_version`（旧消息为 1，
受控图片正文为 2）。旧消息的任意 URL 图片不能因升级被自动授权；新读取器兼容无标记旧消息。
图片校验失败时也保留有界不可用记录或内联说明，不能伪造 blob 或来源绑定；只有真实有效来源可签发授权。
最终归一化规则为：纯图请求且有有效图片时为 `images`；有正文文字和答案图片时为 `text_and_images`；
其余可见文字结果为 `text`。附件全部失败的原纯图请求降级为文字说明，并保存最终的 `text` 状态。

<a id="s7-3"></a>

### 写入一致性

先将校验后的图片写入归档，再在同一数据库事务内完成消息、来源和附件记录。
文件系统使用原子落盘；S3 先提交 uploading 预约、在事务外上传/验证，再在完成事务内 CAS ready，
不承诺 S3 与 SQLite 的跨存储原子性，详见 [10](10_blob_storage.md)。
公开调用还需与 run 的 `completed`、保存的响应和幂等结果共同提交，不能分两次标记成功。

数据库提交失败时，不返回可访问附件；未引用归档文件由有保留窗口的孤儿清理回收。
文件系统错误等预期附件失败不撤销已经生成的文字答案，但必须记录原因并把该附件标为不可用。
数据库事务失败、取消、权限冲突或未知程序错误仍遵守原有执行失败语义，不宽泛吞异常。

<a id="completion-projections"></a>

#### 规范结果与公开结果的写入来源

归档服务先生成严格类型的内部完成结果，包含规范正文、最终格式/输出模式、来源、附件及不可用原因。
控制台阻塞响应、done 和历史读取均从该完成结果投影；公开调用额外生成标准 Markdown，URL 模式签发 grant。

| 持久化目标 | 写入来源 |
| --- | --- |
| `messages.content`、下一轮模型历史 | 内部规范正文；只含受控逻辑标记或失败说明，不含 grant URL |
| 消息格式/模式、来源及 `message_images` | 同一内部完成结果的最终状态 |
| `run.result_json` | URL 模式保存公开标准投影及已签发链接；Data URL 模式保存有类型的无 Base64 投影描述，见 09 |
| 原生 API、OpenAI content、幂等重放 | service 从上述持久化结果加载公开投影；Data URL 的重放须重新授权并从原始字节重建 |

当前 `ApplicationRunRepository.complete(run_id, response, raw, retention_days)` 已有 `response` 和 `raw`
两组输入；实现时明确其类型及上述映射，把写消息的 `answer` 改为内部完成结果中的规范正文，
不能继续取 `response["answer"]`。可以沿用并收紧现有参数，也可按需增加内部类型，
不强制拆分方法签名，不让 repository 返回 HTTP DTO。消息、附件、grant、run 结果在同一事务提交；
仅在提交成功后才能对外输出最终结果。当前 `complete_turn` 返回 None 不妨碍使用已分配消息 ID 构造结果。

<a id="transport-projection"></a>

### 图片传输投影

图片存储格式与对外传输格式严格分离。`answer_image_blobs` 始终保存经校验的原始二进制，
不把 Base64 写入 `messages.content`、Agent 历史、附件元数据或 `run.result_json`。
传输层定义：

| `image_transport` | 返回形式 | 适用场景 |
| --- | --- | --- |
| `url`（默认） | 控制台私有 content URL；公开 API 的带 grant URL | 浏览器、SDK、普通 API；支持懒加载及独立授权/刷新，缓存仍按 no-store |
| `data_url`（显式请求） | `data:<verified-media-type>;base64,<payload>` | 客户端无法访问图片服务、受限网络或需要单响应携带小图片 |

`data_url` 使用标准 Base64，无换行；MIME 只能来自图片解码校验结果，不能使用客户端或模型自报值。
图片仍先经过同一授权、来源和完整性检查；生成 Data URL 不需要额外 grant，但已经返回的字节无法被撤回，
所以它只允许在明确请求、预算通过且响应即将返回时生成。URL 模式仍按现有 grant、过期和刷新规则执行。

公开 API 的 `image_transport` 进入请求 fingerprint：同一幂等键不能在 `url` 与 `data_url` 之间切换。
`data_url` 重放不把 Base64 写进持久化快照；以严格类型的版本化投影描述保存有序正文模板、
附件绑定、公共元数据和完成时预算结果。在来源不变、结果有效且原始 blob 可读时确定性重建；
撤销后不再返回字节，改为不可用投影；到期返回 410，不换图、切换 transport 或重新执行模型。
详细输入/输出类型、快照兼容、预算和流式边界统一见 [09 图片传输](09_transport.md)。

控制台第一阶段固定使用私有 URL，保留懒加载、`no-store` 和附件归属校验；不把整张图片编码进 SSE 或历史响应。
公开 URL 仍不要求客户端访问底层对象存储，只需能访问 Nianlun 的公开图片接口；网关/服务端负责读取归档文件。
OpenAI 兼容响应的传输模式见 [公开输出](06_openai.md#s10-1)，视觉模型内部输入的 Data URL 不等于对外响应模式。

<a id="blob-storage-backends"></a>

### 可选存储后端

`ImageBlobStore` 统一 put/open/stat/delete，负责 IO，不负责应用鉴权和引用事务。
默认 `filesystem`，可配置 `s3` 接入 MinIO/AWS S3；SQLite 保存定位/权限，归档保存原始二进制。
本模块下述 POSIX 锁仅适用于本地文件；S3 使用 [10](10_blob_storage.md#storage-port) 的不可变 key、
状态 CAS 与租约/回收声明。公开图片仍由 Nianlun 代理，不暴露存储凭据或直接返回对象签名地址。
只切换图片归档后端，不迁移 01 的本地工作区，也不自动赋予当前 SQLite 多主机部署能力。

#### 来源、删除与媒体锁

归档文件存在不代表来源仍可访问。附件提交必须在同一个 SQLite 写事务内，重新检查
知识库和文档的当前有效状态，以及对应文档是否已有已提交的删除 tombstone。
文档正常更新不使旧版本失效；文档不存在、知识库不存在或已删除时，不创建有效来源绑定，
不签发 grant。来源检查、绑定写入和 run/消息完成不得拆成独立事务。

删除操作也必须在提交 tombstone/知识库删除的同一事务中撤销已有来源绑定及关联 grant。
SQLite 写事务串行化后，两种提交顺序都必须成立：

- 附件先提交：后提交的删除事务能找到并撤销该附件的来源。
- 删除先提交：后提交的附件事务发现来源无效，不得重新激活它。

来源全部失效时保留文字答案，只移除对应图片；已归档但未被引用的文件进入孤儿回收。
该处理不取消其他仍有有效来源的图片，也不能把权限失效静默改成读取新版本资源。

本地文件后端的归档写入、复用和回收必须共用媒体资源锁，保留窗口不能替代互斥：

- 锁以 `(knowledge_base_id, sha256)` 为键，采用进程内线程锁与 POSIX 文件锁组合，
  同一存储的所有归档、复用和 GC 入口必须遵守。锁文件位于固定维护目录，
  不随知识库或 blob 目录删除，不在释放锁时删除，以免并发进程锁住不同文件。
- 一轮在冻结的资源预算内确定候选身份及摘要，再按固定键顺序取得全部所需媒体锁。
  从检查已有文件、摘要校验、必要的原子写入，一直持锁到附件完成事务提交或回滚。
  复用旧 blob 也执行相同检查；不能因数据库已有记录就跳过文件校验，也不能在锁外提前检查后直接提交引用。
- GC 的初次扫描只提供候选。取得同一媒体锁后，在数据库写事务中重新检查附件引用和保留时间；
  有任何仍保留的附件引用时不删除。只有确认为可回收时才移除文件和 blob 记录，
  全程持锁至事务结束。不能拿扫描时的“无引用”结论在锁外删除。
- GC 先执行时，后来的归档请求在锁内发现文件缺失，须从仍持有有效 snapshot 引用的来源重建，
  校验成功后才能提交新附件；归档先执行时，GC 等待后必须看到新引用并跳过。
  重建失败遵守附件不可用规则，不提交指向缺失文件的可用附件。
- 锁顺序统一为维护锁、必要的 workspace 锁、按键排序的媒体锁、数据库事务。
  删除事务只撤销绑定和安排回收，不在已持有数据库写事务时反向申请媒体锁或直接清空归档目录。
  媒体锁不覆盖模型调用或网络传输；图片读取在同一锁内完成授权检查和文件打开，
  使用已打开的文件句柄传输，避免授权通过后尚未打开文件就被并发清理。

本地文件删除与 SQLite 事务不能组成跨存储原子事务。GC 中断后，允许出现无引用的残留 blob 记录
或文件，由后续清理在同一锁协议下幂等处理；不得把这类残留视为可复用的完整资源。
S3 不使用上述文件句柄/锁协议保护远端对象；由 10 的 ready/deleting CAS 和有效读取租约保护，
网络 IO 在 SQLite 事务外执行，回收失败保留声明重试。
失效 uploading 或确证缺失/损坏的 ready 按 [10 的恢复规则](10_blob_storage.md#blob-recovery) 退役，
释放活动摘要约束；新请求只能从有效 snapshot 中校验同摘要字节后建立新 blob，不自动改绑旧历史附件。

<a id="s7-4"></a>

### 删除与撤销

- 文档正常更新：旧消息继续展示归档原图，新回答使用最新已提交版本。
- 原文档或知识库被删除：撤销对应来源绑定；附件已无有效来源时，撤销其访问和公开 grant，历史消息保留“原图已删除”的占位，不继续提供归档字节。
- 会话删除或到达下述图片结果保留期限：撤销附件访问、解绑 blob，引用归零的归档文件可回收；历史仍保留时保存不可用占位。
- 文档、知识库、会话删除和 blob/孤儿 GC 均不得删除、移动或替换固定维护目录及其中的共享媒体锁文件；
  即使资源已无引用，也不清理锁文件，避免后续进程锁住不同 inode。清理入口审计须覆盖此约束。
- 同一文件被其他文档或消息合法引用：只撤销目标附件，不能删除仍被其他有效附件使用的 blob。
- API 客户端禁用、应用渠道停用或 Key 撤销：公开图片读取同步校验；Key 轮换不自动撤销同客户端其他有效 Key 取得的授权。

“更新保留、删除撤销”是本设计明确采用的历史行为。浏览器或调用方已经下载的副本无法收回。
附件仍有有效来源时，展示引用只包含有效绑定；客户端历史缓存中的旧来源编号不能恢复已删除来源的访问。

所有图片读取和 grant 刷新还必须重新检查来源对应的文档、知识库和会话是否存在且未删除，
不能只相信附件上缓存的 `available` 状态。检查失效时拒绝读取并触发状态修复。
会话 checkpoint 过期仅禁止续聊，不等于删除会话，也不提前撤销仍在结果保留期内的图片。
图片读取的授权检查是访问的判定时点；删除提交前已通过检查并开始传输的响应可以结束，
删除提交后的新读取必须失败。若文件读取失败，不允许重新解析当前文档来替代旧图。

<a id="retention-lifecycle"></a>

### 生命周期与清理责任

续聊期限、结果保留和单次链接有效期独立计算，统一使用 UTC；请求读取时即检查截止时间，
不能等后台清理后才生效。以下公开结果策略在第二阶段启用，不借第一阶段升级清理已有数据。

| 对象 | 保留规则 | 到期/删除行为与责任 |
| --- | --- | --- |
| 控制台消息及图片附件 | 无自动 TTL，保留至明确删除或来源撤销 | 会话删除事务撤销访问并解绑；图片服务回收零引用 blob |
| API/WeCom 续聊 checkpoint | 沿用现有会话续聊期限及活动时间更新 | 现有 checkpoint 清理器只清 checkpoint、标记上下文过期；不删除结果或附件 |
| 第二阶段起新完成的公开 run 结果及其图片附件 | 完成时冻结 `result_expires_at`，默认完成后 30 天；新增独立结果保留配置，续聊不延长它 | 查询、幂等重放和刷新到期返回 410；图片服务按 run 截止时间撤销 grant、使附件不可用并解绑 blob |
| 升级前的旧 run | 迁移后的 `result_expires_at=NULL`，沿用现有文字结果保留行为 | 不自动回填截止时间或删除旧数据；允许历史文字结果读取，但禁止图片 grant 签发/刷新和 Data URL 投影；如需历史图片公开须显式迁移并设定截止时间 |
| 公开 grant | 新完成 run 使用 `min(签发时间 + 24 小时, result_expires_at)`；更早的撤销优先 | 到期读取 410，可在结果期限内显式刷新；过期/撤销记录在所属结果有效期内保留。`result_expires_at=NULL` 的旧 run 不满足签发条件 |
| 无附件引用的孤儿 blob | 默认宽限 24 小时 | 本地媒体锁/S3 状态 CAS 加租约复查后幂等回收；有有效引用的 blob 不按年龄回收 |

结果期限配置命名为 `application_api_result_retention_days`（默认 30），孤儿宽限配置命名为
`answer_image_orphan_grace_hours`（默认 24），均须为正数。环境变量沿用项目命名规则；
新增配置及旧库升级测试同步到 settings、`.env.example` 和 migrations。WeCom 当前无图片附件，
仍沿用文本行为；第二阶段统一结果保留策略须同时覆盖其 run 查询及内部重放入口。

图片服务的周期清理先在数据库事务内撤销授权、把保留的附件元数据改成不可用、解绑 blob，
并清除已超过查询期限的公开响应快照；事务提交后再按本地媒体锁/S3 回收声明协议回收零引用资源。
不自动删除规范文字历史、来源审计或 run 的最小幂等记录。过期幂等键继续命中 410，
不能因清空 `result_json` 重新执行模型；确需重跑应使用新键。显式删除 run 后按删除契约返回 404。
grant 在结果到期后可随清理删除，已清理的未知 grant 返回 404；仍有记录的过期 grant 返回 410。
对旧 run 的 grant 签发/刷新遇到 NULL 截止时间时返回明确的“历史运行不支持图片授权”错误，
不把 NULL 当成无限期，也不擅自用当前默认 30 天补填。

清理可重试，与 checkpoint 清理解耦。并发刷新必须在同一写事务复查结果截止时间；
读取复查 run、附件和来源，避免清理尚未执行时仍提供已过期图片。清理不改写仍在保留期内的幂等快照。
历史加载同样检查附件所属 run 的截止时间；已过期图片返回不可用状态，不从尚未清理的 blob 恢复访问。
控制台旧会话的工具/prompt 契约迁移见 [发布与续聊兼容](02_agent.md#release-compatibility)。
