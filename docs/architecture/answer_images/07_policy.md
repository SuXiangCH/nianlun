## 文件类型、限额与错误

首版仅允许经文件签名、尺寸和内容校验的 PNG、JPEG、WebP 静态图。
拒绝 SVG、HTML 和动画图片；不信任文件扩展名或模型生成的 MIME。

<a id="image-decoder"></a>

### 可信图片元数据与解码

第一阶段使用 Pillow，依赖与锁文件在实施时同步更新，不使用已被 Python 3.13 移除的 `imghdr`，
不手写通用图片解码器。目录生成和归档/复用验证共用同一校验器：

1. 限制本地文件读取大小，先检查字节上限再交给解码器；在受限文件句柄上打开，禁止网络读取。
2. 限定实际格式为 PNG/JPEG/WebP，读取尺寸、帧数，先检查像素上限及静态图条件再完整解码。
   Pillow decompression-bomb 警告按拒绝处理，不能通过全局关闭防护让文件通过；显式预算仍按请求冻结。
3. 校验完整性并完整加载像素，拒绝截断/损坏数据；需要重新打开时沿用同一受控资源，
   使用上下文管理器及时释放句柄与解码内存。伪扩展名不决定格式，未支持的 GIF、SVG、HTML 均拒绝。
4. 目录的 `media_type/size_bytes/width/height/sha256` 来自上述验证及原始字节。
   通用 normalized artifact 可继续使用 `application/octet-stream`，不能把它当作最终可信图片 MIME；
   不要求为本功能重写通用 artifact schema。

保留原始字节，不做 EXIF 旋转或转码；目录记录原始像素尺寸及有界方向信息，
展示层按浏览器方向处理后的宽高比预留空间。CMYK JPEG 由解码器验证，若格式支持且校验成功可保留。
解码依赖纳入常规安全更新，升级需重跑本地格式 fixture 与畸形图片测试。

### 请求资源预算

不设两张的固定展示上限；以下是可配置的初始资源预算，实施时进入严格类型的图片策略，
在请求受理时冻结并传递给检索、工具、回答和归档，不按共享 runtime 的状态动态变化：

| 预算 | 初始值 | 达到预算时 |
| --- | --- | --- |
| 单图 | 8 MiB、4000 万像素 | 标记该图不可展示，保留原位说明 |
| 本轮候选目录 | 64 个唯一图片引用，计入模型总输入 token 预算 | 返回总数/截断状态；目录只承诺已返回集合 |
| 答案实际资源 | 32 张唯一图、合计 128 MiB | 普通回答保留超出位置及 `budget_exceeded`；纯图工具提前报预算错误，允许修正或分批 |
| 附加来源预览 | 最多 8 张、32 MiB，且不能侵占答案资源预算 | 来源面板说明未归档数量，不伪装成没有原图 |
| 正文图片标记次数 | 128 次，重复图也计数 | 超限按有界输出错误结束，不无限解析或静默截断 |
| 单图片候选行/公开流式缓冲 | 4 KiB / 1 MiB UTF-8 字节，且不超过现有响应大小限制 | 超限明确报错并释放资源，不以删除后续内容换取成功 |

32 张是部署可调的防护预算，不是 UI 只展示前几张的规则；在预算内引用 3、10、20 张都完整展示。
回答输入明确提供当前资源预算，引导大批请求分轮处理。归档按首次引用顺序计算唯一资源预算，
已存在归档文件也按其原始大小计费，不能靠跨会话去重绕过单次限制。
超限图片仍占有界结果位置但不分配 blob/grant；统一 `status=unavailable`、`reason=budget_exceeded`。
可用性原因使用固定枚举并提供同语言展示说明，不能在正文或 API 返回内部路径和异常文本。
控制台及默认 URL 展示不需要 Base64；第二阶段显式 Data URL 模式见下述独立预算。
首版不生成新缩略文件，前端按尺寸约束和懒加载展示。
新配置若采用环境变量，必须同步 `.env.example`、边界校验及配置测试。

<a id="inline-transport-budget"></a>

### 内联传输预算

[09 图片传输](09_transport.md) 定义 Data URL 的配置和完整计费规则：单图默认 1 MiB、
本轮唯一原始字节默认 2 MiB、完整公开原生 JSON envelope 默认最多 8 MiB，并受部署更小限制约束。
编码长度精确按 `4 * ceil(N/3)` 加前缀计算，answer 与 images 重复携带的 payload 各自计费。
正文图片数与原图归档预算仍受本模块限制，不能用编码方式绕过像素或类型校验。
超单图/图片总额按位置标记 `inline_budget_exceeded`，不切换 URL；完整 envelope 超限则失败，不发成功 done。
1 MiB 流式缓冲预算只用于规范正文；内联输出使用独立有界预算，不能直接把编码后图片送入普通图片行解析器。

| 情况 | 行为 |
| --- | --- |
| 普通问答无正文图片标记 | 正常文字答案，不因文字 citation 自动附图 |
| 正文图片超过资源预算 | 保留相应位置的超限说明及不可用元数据，不静默减少展示数量 |
| 未知/越权逻辑引用、模型输出任意 URL 图片 | 原位不可用说明，不创建外部请求或有效授权 |
| 显式索要图片但无有效选择，或选中图片全部不可用 | 返回简短文字说明，不能输出空白成功内容 |
| 路径无效、文件缺失、格式或大小超限 | 不公开该图；记录结构化原因，文字继续 |
| 历史附件已删除 | 保留不可用占位，图片接口 404 |
| token 错误、跨归属、grant 不存在 | 公开图片接口统一 404 |
| 已过期 grant | 公开图片接口 410，接入方可显式刷新 |
| 已过期 run 结果 | 查询/刷新/幂等重放 410；历史图片不可用，reason=result_expired，不重新执行模型 |
| 内联单图或图片总额超限 | 该位置 unavailable，reason=inline_budget_exceeded；不静默改成 URL |
| 归档字节与登记摘要不一致 | 拒绝图片读取并记录完整性错误，不返回其他版本替代 |
| 提交事务失败、请求取消 | 保持原有失败语义，不发成功附件 |

公开图片接口错误采用现有公开原生 API 错误 envelope；OpenAI 调用错误仍使用既有
OpenAI 错误格式。接口日志记录 request ID、run/message ID、附件 ID、原因和字节数，
不记录应用 Key、图片 token、Base64、敏感图题或完整图片 URL。
Base64 脱敏包括公开 answer 和 images.url、异常对象及响应采集，不能仅检查 query token。
ASGI server 与容器访问日志按 [公开访问日志](05_public_api.md#access-logging) 处理；
grant、结果和孤儿资源的时间预算按 [生命周期矩阵](03_storage.md#retention-lifecycle) 执行。
后端配置和网络预算见 [10 图片存储](10_blob_storage.md)；S3 失效不静默切本地，
不把远端 HEAD/ETag 当作已完成字节完整性校验。真实 SDK 调用不放入普通测试或 async route。
