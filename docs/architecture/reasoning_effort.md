# 思考程度配置

## 配置入口与作用范围

| 配置位置 | 可选值 | 作用范围 |
| --- | --- | --- |
| 模型管理 | 不配置、低、中、高 | 使用该模型的调用默认值 |
| 知识库 | 跟随模型、不配置、低、中、高 | 后续文档处理中的 LLM 调用 |
| Agent 创建与草稿配置 | 跟随模型、不配置、低、中、高 | Agent 对话、工具调用与答案生成 |

模型默认不配置；知识库和 Agent 默认跟随模型。知识库的覆盖不会传给 Agent。
修改知识库配置不重建已有索引，只影响后续入队的文档处理任务。

## 解析与请求参数

模型字段 `reasoning_effort` 为 `null | low | medium | high`。
知识库与 Agent 字段为 `inherit | default | low | medium | high`。
`inherit` 使用所选模型的默认值，`default` 明确省略参数，其余值覆盖模型默认值。

“不配置”表示不发送 `reasoning_effort`，由模型服务决定默认行为，不表示关闭思考。
显式设置后通过 OpenAI 兼容接口的 `reasoning_effort` 参数发送，并省略旧的
`enable_thinking=false`。温度独立配置，不因思考程度改变。
不根据模型名称猜测支持能力；连接测试按配置实际调用，不支持时返回供应商错误。

## 独立温度

模型管理的高级设置提供 `temperature`，允许 `null` 或 `0–2` 的数值。
留空表示不发送参数；`0` 是有效的显式配置，可以和思考程度同时发送。
创建、编辑、连接测试、知识库处理与 Agent 对话使用同一模型配置。
摘要、文档描述、标题修复及无标题规划不再在调用时覆盖温度。

新发布版本以 `sampling_config_version=2` 固定模型温度，文档任务在入队事务中
保存温度；后续修改模型不会改变已有版本或排队任务。旧发布版本默认版本号为 1，
保留原先开启思考程度时省略温度的行为，其配置指纹不变。
旧发布版本和缺少温度快照的旧任务保留 SDK 原有的温度校正，避免将历史默认值
强制发送给不支持该值的模型；新配置中的显式温度仍按原值发送。
温度仅在模型管理设置；从版本恢复 Agent 草稿后，后续新版本的温度取当前模型配置。
旧模型升级后温度为 `null`，后续新调用遵循“不配置”语义；不自动重建已有索引。

## 版本与任务快照

- Agent 发布版本保存解析后的值，修改模型默认值不影响已有发布版本。
- 从版本恢复草稿时固定该版本的值；原版本未配置时恢复为 `default`。
- 文档任务入队时，在事务内读取知识库与模型配置并保存解析后的值；排队期间修改配置不影响该任务。
- 旧模型默认值为 `null`，旧知识库与 Agent 默认 `inherit`，旧发布版本默认不发送参数。
- 无思考程度的发布版本沿用原有指纹，数据库迁移可重复执行。

## 验证边界

单元与 API 测试覆盖参数省略、继承、覆盖、更新保留、迁移、运行时传递、任务快照和发布恢复。
供应商具体支持哪些级别以其接口为准，自动测试不调用真实模型。
